# @deepseek-ai/dsh-power-analysis

[English](README.md) | 中文

为光伏微逆、储能、微网控制及相关嵌入式功率软件工作提供可回放、带证据标签的分析状态。

## 功能

该函数插件注册面向模型的 `power_report` 工具，以及从 `/locate`、`/review`、`/incident`、`/requirement` 和 `/fix` 中按权限匹配的命令集。每个已注册命令都要求提供任务，写入初始 `power/analysis-state` 事件，并通过 `agent.followup(createUserMessage(...))` 排入固定领域提示。该提示要求使用证据标签、披露兼容性、提供真实构建回执，并遵守本包禁止硬件执行的规则。

`power_report` 接收完整的当前 `PowerAnalysisSnapshot`，不支持局部更新。快照的 `mode` 与配置权限不一致时会被拒绝。调用成功后，会向调用 agent 的会话追加包含完整变更后状态的 `power/analysis-state` 事件。该事件是 UI／回放状态的权威来源，常规 `tool/call` 和 `tool/result` 记录则完整保留模型看到和提交的内容。

## 配置

`mode` 为 `review` 或 `fix`，保守默认值是 `review`。review 权限只注册 `/locate`、`/review`、`/incident` 和 `/requirement`，且只接受 `mode: review` 的快照；它永远不会注册 `/fix`。fix 权限只注册 `/fix`，且只接受 `mode: fix` 的快照。因此命令表面和报告执行器会执行同一权限，而不是依赖提示措辞或 schema 可见性。

## 快照与投影

schema 版本 1 包含工作流与模式、生命周期状态、原始任务、摘要、带证据标签的声明、发现项、未知项、构建验证、API／ABI／NVM 兼容性、安全边界和 RFC 3339 时间戳。每个状态事件都携带完整快照；回放时后写覆盖先写，不依赖此前的内存状态。

当存在 `ctx.sessionProjections` 时，插件注册 `power/analysis` 键。其初始值为 `null`，无关事件保留同一状态引用，有效的 `power/analysis-state` 事件会整体替换其值。`./client` 仅重新导出客户端安全类型及对 `SessionProjectionMap` 的声明合并。

## 证据规则

每个 `Claim` 只能使用一个标签：`VERIFIED_FACT`、`CODE_INFERENCE`、`ENGINEERING_JUDGMENT` 或 `UNKNOWN`。已验证事实和代码推断至少需要一个精确的 `EvidenceRef`；工程判断同时需要依据和待验证项；未知项需要待验证项。发现项引用的声明标识必须指向同一快照中的声明，重复的声明标识会被拒绝。

证据引用标识来源类别、制品和精确位置，并可选携带修订版本。本包不会虚构证据，也不会推断命令已经运行：它只验证模型提交的报告结构，并持久化被接受的准确状态。

## 构建与兼容性回执

编译是显式的可辨识声明。只有成功回执包含 `exitCode: 0`、准确命令、工作目录、开始与结束时间戳、源码修订版本、工作树 clean/dirty 状态和摘要时，才接受 `build.declaration: compiled`。失败构建要求非零退出码。`not-run` 要求给出原因并将回执设为 null。结束时间戳不得早于开始时间戳。修订版本与工作树状态刻意取代强制 diff 摘要：回执可以记录执行上下文，而无需计算一份本身不能证明命令确已运行的 SHA-256。

API、ABI 和 NVM 的兼容性分别声明为 `unchanged`、`compatible-change`、`breaking-change` 或 `unknown`。任一项声明为破坏性变更时，都必须同时提供迁移与回退说明。

## 安全边界

该 P0 包永远不会授予目标板权限。每个可接受快照都将目标板执行、功率级带电操作、PWM／继电器／接触器／预充物理动作和目标 NVM 清空固定为 `not-performed`，并将目标授权固定为 `not-granted`。它还会尽力拒绝常见的硬件已烧录、上电、复位或动作的肯定性自然语言声明，但自然语言匹配不是授权记录；结构化 `safetyBoundary` 是唯一权威执行状态。工作流提示会重复该限制；本包不包含目标传输、编程器、调试器、串口、PWM、继电器或保护寄存器操作。

只有在已获授权的源码编辑工作流中，才可能进行保护阈值、死区、Trip 配置或安全默认值的源码变更，并且必须用 `SafetyParameterChange` 条目披露旧值、新值、依据和证据。布尔披露标志必须与是否存在条目完全一致。

## 命令

review 配置公开四个只读工作流；fix 配置只公开 `/fix`。后续报告中的模式／工作流不匹配以及配置权限不匹配都会被拒绝。空命令输入会返回 `Usage: /<workflow> <task>`，且不会追加状态或唤醒 agent。命令输入存放在领域快照和排队的模型消息中，因此命令生命周期日志无需重复保存它。

## 不变式配套插件

启用不变式注册表后，`@deepseek-ai/dsh-power-analysis/invariant` 会验证已有以及新追加的本包事件。它先检查事件判别字段和版本，再执行与 `power_report` 相同的完整快照验证。无效的持久状态会明确失败，而不会进入投影值。

## 导出形状

主入口是函数／命名空间插件，导出 `name`、`inject`、`Config` 和 `apply`，不提供默认导出。`./types` 和 `./client` 提供共享的客户端安全词汇；`./invariant` 提供本包的不变式配套插件。

## 模型体验

### 工具 schema

#### 模型看到的内容

模型会看到生成的 [`power_report(snapshot)` schema 目录条目](../../../docs/tool-catalog.md#tool-package-map)。由于可接受格式包含 JSON Schema 无法表达的关联规则，`snapshot` 参数采用 JSON；描述会列出全部必填顶层字段、证据义务、构建回执规则、固定的物理执行值和配置权限。运行时验证会在追加任何领域事件之前拒绝未知键、不完整或相互矛盾的报告，以及与权限不匹配的模式。

#### Token 影响

工具定义带来固定的提示 token 成本。每次调用都会在工具调用历史中保留完整快照，因此在压缩前，token 增长量随声明、发现项和证据数量增加。

#### KV Cache 影响

只要插件可见性不变，定义就保持前缀稳定。被接受的报告参数和精简确认会追加在可复用前缀之后。

### 工作流消息与结果

#### 模型看到的内容

每个命令都会排入一条固定工作流消息，其中包含 JSON 引号包裹的用户任务、工作流专属审查指令、证据标签、回执要求和禁止硬件执行规则。报告成功时返回 `Power analysis snapshot accepted at event <seq>; status: <status>.`。验证失败会成为普通错误工具结果，并保持投影不变。

#### Token 影响

每个工作流以一条有界指令消息开始。报告调用成本与完整快照成正比；投影事件不会派生出隐藏的第二条模型消息。

#### KV Cache 影响

工作流消息和工具结果仅追加。改变工作流选择或工具可见性只会改变请求的后续后缀。

## 已知限制与暂缓事项

- 本包记录证据引用，但不会自行读取源码、数据手册、日志或波形；文件系统、LSP、日志和波形 provider 属于独立能力。
- 两种配置模式只授权源码分析行为，均不会授予目标板执行权限。未来硬件层需要单独审查的授权模型，并且不得重新解释版本 1 的这些 `not-performed` 字段。
- 自然语言执行声明拒绝覆盖常见中英文肯定表述；固定的结构化安全字段仍是可执行的权限记录。
- 本包不解析编译器输出。构建回执只证明实际工具路径提交的命令元数据与退出状态；调用方和审计工具必须将这些字段绑定到捕获到的执行结果。
