# 功率策略

[English](README.md) | 中文

`@deepseek-ai/dsh-power-policy` 为一个 agent（智能体）或 preset 作用域实施失败关闭的工具权限。它不执行硬件操作，也不能挂载到整个进程：作用域挂载是权限与 dispose（资源释放）的单位。

## 配置

| 配置键 | 必填 | 含义 |
|---|---:|---|
| `mode` | 是 | `review` 允许 `read`、`read_image`、`grep`、`glob` 和 `power_report`；`fix` 还允许 `write` 和 `edit`。 |

插件选择原生工具呈现，在 `system-prompt/assemble` 期间移除模式固定 allowlist 之外的全部 schema，并注册单调的 `ctx.tools.guard()`，在执行时拒绝相同名称。守卫是权限检查；schema 过滤会减少意外调用，但不作为强制执行机制。

对于面向模型的文件系统调用，仅校验工具名称并不充分，因此最终守卫还会复查其路径参数。`read`、`read_image`、`write` 与 `edit` 要求字符串 `file_path`；`glob` 与 `grep` 接受可选的字符串 `path`。即使省略搜索路径，每个文件系统调用也必须在会话 header 的 `cwd` 中提供绝对、已存在的目录。显式路径必须非空，按 POSIX 与 Windows 两套规则均须为相对路径，并且按两种分隔符切分后都不能包含父级分量。守卫还检查有限层数的百分号解码视图，从而拒绝编码后的绝对路径与父级遍历。

守卫会规范化会话工作区与每个已存在的目标，仅当目标就是工作区或其后代时才允许调用。搜索、文本读取、图像读取与编辑目标必须已经存在。`write` 可以指向工作区内尚未创建的目标；此时守卫会规范化最深的已存在祖先，并检查预期目标的词法路径。缺少工作区证据、规范化失败，以及当时已解析到工作区外的符号链接或 junction 均会失败关闭。

shell、子进程、外部 Web 或消息外发、目标板与调试器操作、PWM 或功率级动作以及破坏性 NVM 操作会先于普通 allowlist 检查进行分类，并在两种模式下始终被拒绝。这些分类与 allowlist 是安全协议常量，而不是部署可调项。

被拒绝的调用返回 `POWER_POLICY_DENIED `，后跟包含 `code`、`mode`、`tool` 和 `category` 的 JSON。载荷绝不包含工具参数。`HIGH_RISK_TOOL` 用于区分固定安全禁令与 `TOOL_NOT_ALLOWED`；`TOOL_ARGUMENTS_DENIED` 表示工作区路径被拒绝，但不会回显该路径。

所有注册均属于挂载 fiber。dispose 或重新加载策略会恢复周围组合的呈现方式、提示词组装与执行策略。

## 模型体验

### 经过滤的工具目录

#### 模型看到的内容

为受此作用域策略覆盖的 agent 组装的每个模型请求，只会收到其配置模式的原生 schema：`review` 暴露 `read`、`read_image`、`grep`、`glob` 和 `power_report`；`fix` 还暴露 `write` 与 `edit`。本包不添加系统提示词文本。

#### Token 影响

影响是有条件的，且以保留的工具 schema 为上限；被禁止的 schema 贡献零 token。

#### KV Cache 影响

当模式和已注册的允许工具 schema 保持不变时，前缀稳定。切换模式或更改任一保留 schema 会改变工具目录前缀。

## 已知限制与延期工作

- **工作区路径检查是时点检查** — 搜索执行器不会请求 ripgrep 的 `--follow` 模式，守卫也会在分派前规范化已存在的路径分量，但它不会持有原子文件系统租约。因此，拥有更高权限的并发进程仍可能在检查后替换路径分量；部署级沙箱、provider 范围限制与工作区所有权仍是必要条件。
- **其他参数策略仍属于能力所有方** — 最终守卫只验证各文件系统工具的路径字段与会话工作区范围。工具专属的内容、模式、偏移、图像、变更意图与回执校验仍由其所属服务负责。
- **高风险分类是纵深防御** — 无法识别的名称仍会因固定 allowlist 而失败，但在安全词汇明确收录前，其拒绝分类为 `not_allowlisted`。
