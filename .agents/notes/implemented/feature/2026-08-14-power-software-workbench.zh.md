# Agent Note: 可扩展功率软件工作台

Status: implemented

[English](2026-08-14-power-software-workbench.md) | 中文

## 问题

已发布 Web Client 提供通用会话与轨迹界面，但没有围绕嵌入式功率软件证据组织的一等桌面工作区。仓库报告要求提供功率 UI，同时不能让浏览器耦合调试器或设备 SDK。社区 TUI 候选可以作为交互参考，但当前候选要么依赖 Harness rc.6（本工作区为 rc.5），要么作为独立 HTTP 客户端运行。在可视化契约尚未稳定前直接引入，会过早制造版本或生命周期边界。

## 决策

把 `@deepseek-ai/dsh-client-ui-power-workbench` 作为默认的纯 Client Cordis 插件加入。它在 Chat 与 Trajectory 之间注册桌面式 `conversation.view`，且只渲染从共享 Session snapshot 派生的事实。它没有 Host 半边、设备 SDK、命令按钮或任何真实状态写入路径。

视图壳层只拥有布局。三个具名、session 作用域的 list slot 分别承载概览、主工作区和检查侧栏。默认面板通过第三方面板也会使用的同一公开 slot 机制注册，因此领域功能可以独立增加、移除或替换，无需修改壳层。owner currency 保持目标无关，并明确排除硬件遥测。

产品文案直接说明执行边界：浏览器展示意图与证据；未来经过独立审查的网关将独占调试或通信传输；MCU/FPGA/硬件 Trip 保留实时控制与最终保护所有权。较低风险验证阶段的授权不会自动传递到更高风险阶段。

## 曾考虑的替代方案

**立即安装社区全屏 TUI。** 当前基线不采用：已检查的 Cordis 原生候选面向 rc.6，独立 Ink 客户端则经 HTTP 连接而不参与进程内 Client 生命周期；两者都不是当前 rc.5 默认 bundle 的安全即插即用依赖。

**创建第二套 Electron 或终端桌面运行时。** 不采用：在领域界面与扩展契约稳定前，这会重复生命周期、设置与分发工作。

**构建单体功率仪表盘组件。** 不采用：每增加波形、构建、源码或目标适配器都要改动同一个涉及安全语义的展示模块。具名子 slot 保持独立所有权与卸载边界。

## 后果

默认 Web 组合现在提供响应式功率软件桌面视图，且不新增外部生产依赖。单元测试固定 Session 派生和注册/卸载契约；装配浏览器测试证明已发布 Loader 会挂载该视图、子 contribution 及窄视口布局。硬件数据与目标动作仍留给另行授权的 Host 插件。因此，当前可见卡片是可扩展的信息架构，不代表目标连接或电气测量已经存在。
